What AROSA is—and what it isn't.

What does AROSA stand for?

Application Runtime Operating Services Abstraction. It is an independent application platform specifically being developed for AROS.

Is AROSA an official part of AROS?

No. AROSA is an independent project by DaniloS. It is not an officially endorsed AROS distribution, fork or replacement. The name acknowledges its intended host platform; the project should not be confused with AROS itself.

Is AROSA just a theme or desktop replacement?

No. It includes an architecture for reusable services, capability provision, consumption, discovery and composition. Workspace personalities and desktop features are one part of the larger platform.

Does AROSA replace Exec, Intuition, Zune/MUI or AROS libraries?

No. It builds on the underlying AROS environment, reusing its mechanisms where suitable and offering additional coordination at the application-platform level.

What is a personality?

A workspace-scoped user experience comprising presentation, interaction preferences and available tools. It is broader than a theme and does not grant security permissions. Zune/MUI is being specified as an optional personality, distinct from a historic Workbench 3.1 experience.

Can I download or build AROSA?

The complete AROSA platform is not yet available as a general-availability release. Developers can explore the historical x86_64 AROSA SDK and the separately published AFileManager application source.

Is AROSA open source?

The complete AROSA platform implementation is not publicly distributed. The historical AFileManager application source is published under MPL-2.0, and the compiled AROSA SDK has its own developer license. Each component retains its applicable licensing terms.

How mature is it?

AROSA contains active implementation work and compiled components, but functionality is at different stages. Some subsystems remain experimental or design-only. Production readiness is further constrained by current host operating-system stability and incomplete end-to-end testing.

Can I help?

Technical feedback, use cases and responsible public reports are welcome. See community participation. The internal source repository and engineering tracker are not public.
