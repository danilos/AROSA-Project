AROSA Written for AROS.

AROSA is building a capability-oriented application environment for AROS: reusable services, providers, adapters and composition that applications can use—and contribute to.

Explore the architectureView the roadmap
Development status: Active, multi-track engineering. Some components have working builds; others are experimental, partially integrated or planned. Not a production-ready distribution.
The idea

From isolated applications to shared capabilities

AROSA treats functionality as capabilities that can be advertised, discovered, selected and composed. A file manager, browser or developer tool can consume common facilities instead of implementing each one independently.

AROS remains the underlying operating system. AROSA adds application-level coordination, resource semantics, policy and user experience above it.

One coherent platform

Independent workstreams. Shared infrastructure.

Development proceeds in parallel, with integration and verification across services—not by waiting for each area to be fully completed.

01

Foundation & composition

Service contracts, capability resolution, messaging, state, lifecycle and shared diagnostics.

02

Security & sessions

Identity, authorization, policies, vault capabilities and session-aware services.

03

Content & documents

Repositories, versioning, metadata, aspects, search, preview and transformations.

04

Workspaces & personalities

Workspace-owned experiences, interface customization, launch surfaces and application coexistence.

05

Graphics & media

2D/vector graphics, font and image providers, multimedia and exploratory rendering capabilities.

06

Applications & engineering

File management, browsing, administration, AIDEa tooling and installation workflows.

These are capability areas at varying development maturity—not a checklist of finished features.

Practical example

One document, multiple applications

A document preview can be composed from an authorized content resource, an appropriate format provider, optional transformation and a presentation surface. The same capability can then be requested from different applications.

This illustrates the architectural direction. Supported formats and runtime behavior vary by provider and release.

1Application requests previewCapability contract, not a hardwired parser
2Policy and provider resolutionAuthorization and available implementations
3Content and transformationCorrect representation and version
4PresentationReusable viewer within the user environment
Development reality

Active engineering, not yet publicly released

AROSA has substantial active development, including Foundation services and applications, but production readiness is a separate question from implementation breadth. Current testing also encounters unresolved stability issues in 64-bit AROS/SMP environments.
