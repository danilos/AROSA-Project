Public development overview · November 2026

A parallel roadmap, not a serial checklist.

Foundation, applications, security, content, user experience, networking and testing advance together through integration checkpoints.

Current status: Early development preview. No fixed release date, general-availability binaries or production certification are announced on this site. Progress descriptions are qualitative, not measured completion percentages.

What “implemented” means

AROSA distinguishes design, source implementation, compilation/linking, host tests, AROS guest tests, ISO staging and actual user acceptance. A compiled service is not automatically a reliable deployed service. A specification is not automatically a working feature.

Current technical constraints

The underlying 64-bit AROS/SMP environment exhibits unresolved stability issues, which limit current end-to-end reliability. Browser stability, workspace lifecycle, installation verification and office-format interoperability also remain development priorities. Fault attribution is investigated rather than assumed.

Release principles

  • Build and integrate shared components without silently removing prior functionality.
  • Keep multiple development areas active and use cross-service integration tests.
  • Prefer incremental, versioned features with explicit test evidence.
  • Do not announce a release date or availability until tested artifacts exist.
