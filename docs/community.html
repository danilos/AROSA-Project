Public participation

Constructive technical discussion is welcome.

What could a capability-oriented application environment enable on AROS? What interfaces, failure modes or interoperability concerns deserve attention?

Good topics for discussion

  • Realistic application use cases for shared content, graphics, search, authorization and UI capabilities.
  • Comparisons with existing AROS mechanisms and modern service-oriented architectures.
  • Compatibility, performance, lifecycle, reliability and API design trade-offs.
  • Accessible user experiences and third-party application integration.
  • Usable documentation, demos and test scenarios.

Where to participate

Use the public repository's Issues section for reproducible public bugs, documentation improvements and specific enhancement requests. Discussion facilities may be enabled later. Public issues are not the private engineering backlog and need not reveal internal implementation details.

Open public issues

Public issue guidelines

Describe observed behavior and the environment in which it occurred, and distinguish facts from hypotheses. Do not include credentials, addresses, unpublished source, memory dumps, private internal logs or personally identifying information. Security-sensitive reports should not be posted publicly; see the repository's SECURITY.md for reporting guidance.

Project ownership
